1What your website actually is

Your website, Noor al-Hidayah, is not one single "program." It is a folder of plain text files that a web browser (Chrome, Safari, Edge) reads and turns into the page you see. There is no hidden server doing calculations somewhere — everything happens right inside the visitor's own browser.

Think of it like a recipe book. The file index.html is the recipe card that lists the ingredients and the order of steps. The browser is the cook: it reads the card and produces the finished dish (the page you see) fresh, every single time someone visits.

Because it's "just files," anyone can host it for free — which is what GitHub Pages does for you. Your files live at github.com/ShoiabGoku/islamic-search, and GitHub Pages serves them to the world at https://shoiabgoku.github.io/islamic-search/.

2The three languages: HTML, CSS, JavaScript

Every website on the internet — yours included — is built from exactly three building blocks. Once you understand what job each one does, the rest of this guide will make sense.

LanguageJobAnalogy
HTMLThe content and structure — headings, paragraphs, buttons, imagesThe skeleton of a body — bones that give it shape
CSSThe appearance — colours, fonts, spacing, layoutThe skin, clothes and make-up — how it looks
JavaScriptThe behaviour — what happens when you click, type, or scrollThe muscles and brain — what moves and reacts

In your site, all three live inside one file, index.html — HTML content at the top, CSS rules inside a <style> block, and JavaScript inside a <script> block near the bottom.

3The files in your project, one by one

Here is every file in your project folder and what it's for, in order of importance.

index.htmlthe whole website

This one file contains everything a visitor sees and everything the page does: the daily reminder, the search box, the Maraji cards, the Qur'an reader, the quiz, the prayer-times tool — all of it. It's large (~140,000 characters) because your site does a lot, but it's still just one recipe card.

library/ (folder)your content, kept separate

Instead of typing the entire Qur'an directly into index.html, the actual text lives in separate files inside the library folder — quran.js, nahj.js, duas.js, events.js, quiz.js, and a hadith/ and fiqh/ sub-folder. This keeps index.html manageable and lets the browser only download a book's text when you actually open that book.

manifest.jsonmakes it installable

A small file that tells a phone "this website can behave like an app" — it gives the app a name, an icon, and a colour, so visitors can tap Add to Home Screen.

sw.jsservice worker

A background helper script explained fully in Section 11. In short: it makes sure visitors always get your latest changes and never get stuck seeing an old, cached version.

icon.svgthe app icon

A small image (in SVG format — a format made of shapes and math instead of pixels, so it stays crisp at any size) used as your site's icon.

.nojekylla GitHub instruction

An empty file whose only job is to tell GitHub Pages "don't try to process my files, just serve them exactly as they are." Without it, GitHub sometimes ignores files/folders that start with an underscore.

README.mdthe project's front page on GitHub

A plain description of the project, written in Markdown (a simple way to write bold text, headings, and lists using symbols like **bold** and #). GitHub automatically displays this file on your repository's homepage.

4How the page is structured (HTML)

HTML is built from tags — words wrapped in angle brackets, like <p> — that label a piece of content. Most tags come in pairs: an opening tag and a closing tag (with a forward slash) that wrap around the content they describe.

<h2>Search the Words of Guidance</h2>
<p>Search in English or Arabic across the Qur'an...</p>

This says: "Here is a heading, and here is a paragraph." The browser turns that into large bold text followed by normal text.

HTML tags are like labelled boxes in a warehouse. <h2> is a box labelled "big heading," <p> is a box labelled "paragraph text," <button> is a box labelled "clickable button." The browser looks at the label on each box and displays its contents accordingly.

The tags your site uses the most

TagWhat it means
<section>One whole "chapter" of the page — e.g. the whole Quiz area, or the whole Search area
<div>A generic container/box, used to group things together for styling
<h1> <h2> <h3>Headings, from biggest (h1) to smaller
<p>A paragraph of text
<button>A clickable button
<input>A box the visitor can type into (like the search bar)
<a href="...">A link to another page or website
<select>A dropdown menu (like choosing a sūrah)
<svg>A small drawing made of shapes — used for the rotating star and icons

Attributes — extra instructions inside a tag

A tag can carry extra information called attributes, written inside the opening tag as name="value".

<input type="text" id="q" placeholder="Search a topic..." />

type="text" says "this is a text box." id="q" gives this exact box a unique name-tag, "q", so JavaScript can find and read it later. placeholder="..." is the grey hint text shown before you type.

Why id matters: every important box in your site has an id — a unique name tag. JavaScript uses that name tag constantly to say "go find the box called q and do something with it." You'll see id="..." everywhere, and getElementById('q') in the JavaScript is simply "go fetch the box with this name."

5How it looks the way it does (CSS)

CSS rules follow one simple pattern: "select something, then describe it."

.btn {
  background: linear-gradient(160deg, var(--green-700), var(--green-600));
  color: var(--cream);
  border-radius: 12px;
  padding: 13px 22px;
}

This says: "Find everything with the label btn (a button), and make it have a green gradient background, cream-coloured text, rounded corners, and some internal spacing."

If HTML is the skeleton, CSS is a big style sheet handed to a tailor: "every box labelled btn gets this fabric, this cut, this trim." Change the sheet once, and every button on the whole site updates instantly.

The dot, the hash, and how CSS finds things

SymbolMeaningExample
.nameA class — a label that can be reused on many boxes.btn styles every button
#nameAn ID — a unique name for exactly one box#search styles only the search section
tagEvery box of that HTML typeh2 styles every heading-2

CSS variables — one dial that controls many things

:root {
  --green-800: #0e3d2e;
  --gold: #c9a24a;
}
h2 { color: var(--green-800); }

Near the top of your CSS, a handful of colours are defined once, given nicknames like --green-800 and --gold. Every other rule then says var(--green-800) instead of typing the colour code again. If you ever want to change your whole site's shade of green, you change it in one place and it updates everywhere.

Dark mode & responsive design

You'll notice rules like body.dark .res { ... } — this means "when the page has been marked as dark mode, restyle this element." And rules inside @media(max-width:820px){ ... } only apply on small screens (phones) — this is how the site rearranges itself to fit a phone screen.

6How it "thinks" and reacts (JavaScript)

JavaScript is the only one of the three languages that can actually make decisions and respond to actions. Everything interactive on your site — search, the quiz, dark mode, the prayer-times lookup — is JavaScript.

Variables — labelled boxes that hold information

let score = 0;
const greeting = "Assalāmu ʿAlaykum";

A variable is a named container for a value. let means "this value can change later" (like a running quiz score). const means "this value is fixed and won't change" (like a fixed greeting text).

Functions — a saved recipe you can reuse

function tasbihTap(){
  tasbih.c++;
  tasbih.total++;
  tasbihRender();
}

A function is a named block of steps you can run over and over just by calling its name. This one, tasbihTap, runs every time you tap the Tasbīḥ counter's "+1" button: it adds one to the count, adds one to the total, and redraws the number on screen.

A function is like a saved recipe card you can hand to the cook (the browser) any time you want that dish made again — instead of rewriting the whole recipe every time, you just say the recipe's name.

"If this, then that" — conditions

if (tasbih.c >= tasbihCycle[tasbih.i][1]) {
  tasbih.c = 0;
  toast('Well done!');
}

"IF the count has reached the target, THEN reset it to zero and show a little congratulations message." This is how your site makes decisions — checking a condition, and only doing something if it's true.

"Do this for every item" — loops

maraji.map(m => `<div>${m.n}</div>`)

You have a list of 8 Maraji stored as data. This one line says: "for every Marjaʿ in the list, build one little card of HTML for them." That's how 8 cards appear on screen from a single line of code, instead of you having to hand-write 8 separate cards.

Events — "when this happens, do that"

document.getElementById('q')
  .addEventListener('keydown', e => { if(e.key==='Enter') runSearch(); });

"Find the search box (id="q"). Listen for a key being pressed. When that key is Enter, run the search." This pattern — addEventListener — is how your whole site reacts to clicks, typing, and touches. It's the electrical wiring that connects a button to an action.

Objects and arrays — how your data is organised

const marja = { n:"Sayyid Ali al-Sistani", status:"Najaf · Living", books:[...] };
const maraji = [ marja, marja2, marja3 ];

An object (curly braces { }) groups related facts together — like a filled-out index card for one Marjaʿ (name, status, books). An array (square brackets [ ]) is a numbered list of things — like a box holding many index cards, one after another. Your entire Qur'an, all your quiz questions, and all your Maraji are stored exactly this way.

7The "library" data files — your content

Every book on your site (Qur'an, Nahj al-Balāghah, hadith, duʿās, quiz questions, history events) is stored as one big array of objects, saved inside its own file in the library folder.

window.LIB_QURAN = [
  { s:1, na:"الفاتحة", nt:"Al-Fatihah", v:[ [1,"بِسْمِ اللَّهِ...","In the Name of Allah..."] ] }
];

window.LIB_QURAN is the nickname the rest of your code uses to find this data. s is the sūrah number, na is its Arabic name, nt is its transliterated name, and v is the list of verses — each verse itself being a small list of [number, Arabic text, translation].

This is why the library files load with a <script> tag near the top of index.html: they must arrive before the search and reader code tries to use them — like ingredients needing to be on the counter before the cook can start.
FileWhat it holds
library/quran.jsAll 114 sūrahs, 6,236 verses — Arabic + English + Urdu + Farsi
library/nahj.jsNahj al-Balāghah — sermons, letters, sayings
library/duas.jsZiyārāt & duʿās (Kumayl, Nudbah, ʿĀshūrāʾ, etc.)
library/events.jsIslamic history events, four languages each
library/quiz.js, quiz2.jsThe hand-written quiz question bank
library/hadith/*.js, library/fiqh/*.jsAl-Kāfī and other hadith books; the Maraji's fiqh rulings

8Search — how typing a word finds a verse

Search sounds complicated, but it boils down to three plain-English steps, repeated for every item in a list:

  1. Clean up what you typed and the text being searched, so spelling differences don't matter (capital vs lowercase, or Arabic diacritics/vowel-marks) — this cleanup step is called norm() ("normalize") in your code.
  2. Check whether the cleaned-up text contains your cleaned-up search word.
  3. Collect every item where the answer was "yes," and display those as results.
function searchQuran(terms, limit){
  const out = [];
  for (const su of LIB_QURAN) {
    for (const v of su.v) {
      const hay = norm(v[1] + ' ' + v[2]);          // clean up the verse text
      if (terms.every(t => hay.includes(t))) {       // does it contain every search word?
        out.push({ ar: v[1], tr: v[2], ref: su.nt+' '+su.s+':'+v[0] });
      }
    }
  }
  return out;
}

This walks through every sūrah, then every verse inside it, cleans up the verse text, and checks if it contains all your search words. Every match gets added to the results list, which is then shown on screen.

It's exactly like using Ctrl+F "Find" in a Word document — except your code does that "Find" across 6,236 verses (or thousands of hadith) in a fraction of a second, and does it separately for Arabic, English, Urdu and Farsi.

9Talking to the internet (APIs)

Some features — prayer times and the Qibla direction — need information your site doesn't have built in (today's exact prayer times for a specific city depend on the date and your location). For these, your site sends a request over the internet to another organisation's computer and asks for an answer. This is called an API call (API = "a way for one program to ask another program for information").

fetch('https://api.aladhan.com/v1/timingsByAddress?address=Karbala&method=0')
  .then(r => r.json())
  .then(data => ptRender(data));

fetch means "go and ask this web address for information." Because the answer doesn't arrive instantly (it has to travel across the internet), the code says .then(...) — "and THEN, once the answer arrives, do this with it" (in this case, display the prayer times).

This is like posting a letter and waiting for a reply. You don't freeze in place waiting by the mailbox — you go on with other things, and .then() is simply "when the reply letter arrives, open it and do this."
FeatureWhich outside service it asks
Prayer timesaladhan.com — a free Islamic prayer-times calculation service
Qibla directionCalculated directly on your phone using your GPS location — no outside service needed
Reciter audioeveryayah.com — a free Qur'an audio-recitation library
Why these sometimes fail: because your site is asking someone else's computer for an answer, it can only work if (1) the visitor has internet, (2) that outside service is currently online, and (3) the visitor's browser allows the request (e.g. has granted location permission). None of that is something your own code controls — which is why I added automatic retries and clear error messages for these two features.

10Remembering things: localStorage

Normally, a website forgets everything the moment you close the tab. But your site remembers your dark-mode choice, your bookmarks, your tasbīḥ count, and your last-searched city — even after closing the browser. It does this with something called localStorage: a small private storage locker that belongs to your site, saved inside the visitor's own browser.

localStorage.setItem('noor_bookmarks', JSON.stringify(bookmarksList));
const saved = JSON.parse(localStorage.getItem('noor_bookmarks') || '[]');

setItem saves something into the locker under a name tag ('noor_bookmarks'). getItem takes it back out later. Because the locker can only hold plain text, JSON.stringify "flattens" a list/object into text before saving, and JSON.parse "unflattens" it back into a usable list when reading it.

This locker is per-browser, per-device — it's not a shared account. If you bookmark a verse on your laptop, it won't appear on your phone, because each browser has its own separate locker.

11The Service Worker & "offline" behaviour

A service worker (sw.js) is a small helper script that runs quietly in the background, separate from the page itself, mainly used to make websites work offline or load faster on repeat visits by keeping a private copy of files.

Why we changed this: early on, this caused the exact "old version keeps showing up" problem you ran into. The private copy it kept was getting shown to visitors instead of the newest version. I rewrote it into a self-destructing service worker — on your visitors' next visit, it automatically clears its private copy, turns itself off, and steps out of the way, so everyone always sees your latest updates straight from the real site.

Practically, this means: you (and everyone else) will always get the newest version automatically now — no more manual cache-clearing needed going forward.

12Git & GitHub — how changes reach the live site

Every change I've made to your site follows the same three-step journey from "edited file on the computer" to "visible on your live website."

StepCommandPlain English
1. Stagegit add"Mark these changed files as ready to be saved"
2. Commitgit commit -m "...""Save a snapshot of these files, with a short note describing what changed"
3. Pushgit push"Upload that snapshot to GitHub" — this is the moment it reaches the live site
Git is like a save-game system for your website: every commit is a save point you (or I) could rewind to if something ever went wrong. GitHub is the cloud drive that stores those save points and, because Pages is switched on, also serves the latest one to the public as your live website.

GitHub Pages is the free hosting service that watches your main branch (the "official" copy of your project) and automatically republishes your site every time a push arrives — normally within about a minute.

14What to do if something breaks

You don't need to read code to investigate a problem — you just need to know where to look.

  • Hard-refresh first. On the keyboard, press Ctrl + Shift + R. This clears out any old cached version and is the fix for most "it looks wrong" or "it stopped working" reports.
  • Check the address bar says https://. Location, compass and some other features only work on a secure (https) connection — never on a plain file or http://.
  • Open the Console (F12 → Console tab). Reload the page and try the broken feature. If you see red text, that's a genuine code error — copy the exact red text and send it to me; I can usually diagnose it from that alone. If there's no red text but it still fails, it's almost always something outside the code: no internet, a permission the visitor denied, or the outside service (like the prayer-times API) being briefly down.
  • Describe it precisely. "It doesn't work" is hard to fix. "On my Android phone, in Chrome, when I search for صبر, no results appear" is something I can immediately investigate and reproduce.
